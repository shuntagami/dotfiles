# GitとPRの共通方針

この方針は全リポジトリに適用する。Git標準のブランチ・worktree・stashを使い、作業コピーに変更を重複して残さない。

## 作業場所を決める

- 編集前に、シンボリックリンクの実体、対象リポジトリ、ブランチ、worktreeと既存の変更を確認する。
- すでに割り当てられたworkspaceは、その場所を使う。アプリや開発サーバーが参照しているフォルダも同じ。PRにはその場所でブランチを切ればよく、追加のworktreeは必須ではない。
- 別の作業コピーが必要なら、編集前に作る。worktreeを追加しても、画面・開発サーバー・エージェントの作業場所が自動で追従するとは考えない。

## 変更は一か所で管理する

- 編集後に場所を移す場合は、その依頼の変更だけを移す。Gitのcommit、patch、範囲を限定したstashなどから状況に合う方法を選ぶ。
- コピーしただけで移動を完了にしない。移動先で内容を確認し、元に残った自分の変更を整理する。他の作業と同じファイルに変更が混ざっている場合は、ファイル単位でまとめて退避・破棄しない。
- 関係のない変更をまとめてcommit・stash・reset・cleanしない。未追跡ファイルも含めて保全し、復元できる退避を確認してから整理する。

## PRの作成と完了

- push・PR作成前に、作業先と移動元のステージ済み・未ステージ・未追跡の状態を確認する。開始時と比較し、その依頼の変更が別の作業コピーに未コミットのまま残っていないことを確認する。
- PR作成だけを頼まれたときはマージしない。マージ・更新まで頼まれたときは、GitHubの状態だけで完了にせず、使われているローカルの作業場所への取り込みまで確認する。
- 既存の自動同期や `sync.homeBranch` などの運用があれば、それに従う。慣習だけで別のブランチへ切り替えたり `main` にresetしたりしない。
- GitHubでマージしてもローカルは自動では更新されない。fetchと取り込みは必要だが、自動同期がある場合は重ねて独自の同期処理を作らない。
- pullが未保存の変更を保護して止まったら、何が残っているかを先に確認する。自動stashや強制resetで見えなくすることを、変更の整理の代わりにしない。
