# 例外：編集途中の変更を別worktreeへ移す場合

**通常のPR作業では、この手順は使わない。** 今の作業場所でブランチを使い、commit・pushしてPRを作ればよい。ブランチの切り替えと、別フォルダへの移動は別の操作。

ここでは、並行作業などのために、書き始めた変更をどうしても別worktreeで続ける必要がある場合だけを扱う。画面や開発サーバーの参照先も変更する必要があるか、先に確認する。

## 未コミットの変更を、新しい作業ブランチへ載せて移す例

対象ファイルの変更がすべて今回の依頼に属し、これから作業ブランチを作る場合の手順。すでに作業ブランチやPRがある場合は、そのブランチを使い、新しいブランチへ作り直さない。

1. 元のフォルダで、現在のブランチ名と今回の対象ファイルを記録する。同じファイルに別作業の変更もある場合は、このファイル単位の移動手順を使わず、今の場所で続ける。
2. 元のフォルダで `git switch -c <作業ブランチ>` を実行する。
3. 今回の対象だけを `git commit --only -- <対象ファイル>` でcommitする。新規ファイルは先に対象を指定して `git add` する。`--only` は別ファイルのステージ済み変更を含めないが、指定ファイルの変更はすべて含む。
4. 元のフォルダで `git switch <手順1で記録したブランチ>` を実行する。これはフォルダの移動ではなく、そのフォルダに置かれるファイルを最初のブランチの内容へ切り替える操作。今回の変更は作業ブランチのcommitに残る。別作業の変更と衝突して切り替えを断られたら、強制せずここで止める。
5. `git worktree add <移動先のフォルダ> <作業ブランチ>` を実行する。Gitがcommit済みの内容を移動先に展開するので、ファイルを手動コピー・削除しない。

これは移動が必要な場合の例外手順であり、通常のPR作成に「commitしたら元のブランチに戻る」という段階を追加するものではない。

## 移動完了の条件

- 移動先に今回の変更がcommitとして揃っている。
- 元のフォルダには、今回の未コミット差分が残っていない。
- 元のフォルダにあった別作業の内容とステージ状態が保たれている。

途中で止まった場合は、どこまで済んだかを報告し、移動完了とは扱わない。同じファイルの一部だけを分ける場合、`--only` ではその部分だけを選べない。どの変更が担当分かを確認し、ファイル全体を戻して済ませない。

stashを使う既存ツールの移動機能を選ぶ場合も、上の完了条件を確認する。対象ファイルを指定したstashでも別ファイルのステージ済み変更を移動先へ持ち込む場合があるため、部分移動に一律のstashコマンドを使わない。

参考：[git commit --only](https://git-scm.com/docs/git-commit#Documentation/git-commit.txt---only)、[git worktree add](https://git-scm.com/docs/git-worktree)。
